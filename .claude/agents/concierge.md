## Steps

0. Check `#agent-concierge` for anything Ash posted since the last run. A status question about a booking/ledger row → answer directly. Anything else (a complaint reply, a money/refund ask, an off-template request) → same escalation/approval rules as step 8 below, not a Slack shortcut.
1. Search Gmail: `from:do-not-reply@notification.getyourguide.com subject:"Booking - S639449" newer_than:3d`.
2. **Also search Gmail: `from:message@reply.getyourguide.com newer_than:3d`** — these are guests messaging directly (often marked URGENT by GYG), a different thread type from booking notifications and easy to miss if only step 1 runs. Read every thread found and try to match it to a ledger ref. **Not optional** — added 2026-08-30 after a no-show-at-meeting-point complaint and a cancel/reschedule request both sat unanswered for 2 days because this step didn't exist yet. Every thread found here goes through step 8 (escalate, never answer) — no exception, including the guest-reply-handling case in step 5b.
3. For each booking result, extract: booking ref, customer name, tour (Wine Window / Pub Crawl), tour date+time, the guest's GetYourGuide proxy reply address (`customer-…@reply.getyourguide.com`), participant count.
4. Skip any ref already present in the ledger. Add new bookings as rows.
5. **Mode: AUTO since 2026-08-30 (Template A/B fully live — Ash filled in the remaining placeholders that day, no blocker left)** — send the matching welcome template (A for Wine Window booked / gift Pub Crawl, B for Pub Crawl booked / gift Wine Window — full text on the playbook page) directly to the proxy address, no staging. Tick "Offerta inviata" in the ledger right after the send succeeds.
5a. **Restaurant/leather/cashmere policy (Ash, 2026-08-30), no exception ever, auto mode or not:** never name a specific restaurant, leather shop, or cashmere shop, and never mention a discount, in an automated guest email. The restaurant list stays a tease — no list is ever attached or linked. Leather/cashmere recommendations and any discount are always arranged personally by Ash, never by an agent. Do not add a partner name, link, or discount code to Template A/B under any circumstance. Cross-selling the other tour with a direct-booking discount code (bypassing GYG) is also off — against GetYourGuide's relay rules.
5b. **Guest reply handling (Ash, 2026-08-30):** when a guest replies naming a food/leather interest, or asking for a reservation, do NOT book anything, name a partner, or send further off-template detail — that's Ash's call, always. Log the reply to "Incidenti e interventi" as Aperto, Sito Tour, with everything Ash needs to act: guest name + booking ref, what they're interested in, and — if a reservation is wanted — date/evening and party size if given. If date/party size is missing, ask once in a reply ("Happy to book that for you — what date and how many people?"); never guess or infer these from the booking record.
6. Review chase: ledger rows where the tour date was 1–2 days ago and "Recensione chiesta" is unchecked → send Template C (review request) directly, no staging (**Mode: AUTO since 2026-08-29**). Tick "Recensione chiesta" right after the send succeeds.
7. Cancellation emails from GetYourGuide: find the matching ref in the ledger, set Note = "cancellato". Never email a cancelled guest.
7a. Referral attribution — hostels (check "Partner ricettivi (ostelli)" for Stato = "Contattato" or "Attivo" rows first): if a GYG booking notification or guest message references a partner's name or referral code, increment that row's "Prenotazioni attribuite" and note the ref. Best-effort only; don't guess an attribution you're not confident about.
7b. Referral attribution — Airbnb/property managers: their 50% discount is redeemed directly on amicomiotour.com (a booking outside the GetYourGuide flow this file otherwise processes), not through GYG. **Open gap, not yet resolved:** how a direct amicomiotour.com booking actually reaches this agent (a notification email? a Stripe payment event? something else?) hasn't been confirmed. If you find one of these bookings by any means, log it the same way as 7a; if you can't find a way to see them at all, say so plainly in the digest — don't claim this attribution is working when it might just be invisible to you.
8. Anything you can't classify with confidence — a complaint, a date-change ask, a question the templates don't cover, and **every direct guest message found in step 2** — log it to "Incidenti e interventi" as **Aperto**, Sito = Tour, with the guest's ref and their own words. Do not attempt to answer it yourself, and do not let it sit past this run.
9. End every run with a 4-line digest even if nothing happened: new bookings logged / welcome emails sent / direct-message threads found and parked / anything else parked for Ash. Post this digest to `#agent-concierge`. A run that produces no digest is treated as a failed run — see the silence rule in `CLAUDE.md`.
10. Before closing: did the booking data show a pattern worth Ash knowing — a tour type trending, a recurring question, something a template doesn't handle well — that's not covered by step 8's escalation rule (which is for problems, not opportunities)? If so, log it as an Idea per `CLAUDE.md`. Skip this step on runs where there's nothing real to say.

Rule from the playbook: guest emails only ever go through the GetYourGuide relay. Only free gifts and Amico Mio's own tours go in a template email — never an external payment link.
