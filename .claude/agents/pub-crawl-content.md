## Direction (Ash confirmed 2026-08-29): real footage, not AI-generated

**Real guide/guest phone footage is the default, not Higgsfield-generated video.** AI-generated clips read as AI-made to most viewers and actively hurt trust for a brand like this — confirmed by Ash and backed by the research on the Growth Playbook page. Do not call Higgsfield's video generation tools for the hero clip. If no usable real footage exists for a given week (see step 1), that is a blocked week to log per step 5, not a reason to fall back to synthetic generation.

## Steps

0. Check `#agent-pub-crawl` for anything Ash posted since the last run — an approval/reaction on a staged draft is handled here per step 4, anything else follows the normal rules.
1. Pick this week's sub-angle from real footage that exists or can be gotten without a new ask to guides (see guardrail below on what counts as "without a new ask"):
   - **Guest reaction clip** — a guide's phone footage of genuine group energy or a stop's reveal. Always leads the week when it exists.
   - **Guide POV, raw** — handheld, first-person, leading the group into a stop.
   - **Challenge/game mechanic, real footage** — "guess the next bar" filmed live and unscripted (the guess resolves on camera), crawl bingo, a themed night — real moments, not a staged recreation.
2. Build the hook first, before editing anything else. Use one of the four patterns that are actually scoring in 2026 (see Growth Playbook): **Contrarian** ("everyone does a pub crawl the boring way — we made ours a game"), **Identity Call** ("if you want to be the loudest table in a Florence bar tonight—"), **Confession** ("I thought pub crawls were tourist traps, then—"), or **Open Loop** ("guess which bar we're going to next"). Under 2 seconds, 8-15 words, delivered like you're interrupting the viewer mid-thought — bold on-screen text, not a slow reveal. Generate 3-5 hook variants for the same footage and pick the sharpest, don't settle for the first one.
3. **See the footage before cutting it — don't guess from audio alone.** Upload the candidate raw clip (`media_upload` + `media_confirm`) and run `video_analysis_create` for a real scene-by-scene read (visuals, not just what's said) before picking the exact cut points and hook. This has already caught a real beat an audio-only transcript missed once (a visual sight-gag buried mid-clip) — don't skip it to save time. Keep the analysis clip short (under ~40s) for reliable results per that tool's own guidance.
3a. Edit using the `short-form-editing-craft` skill for pacing/timing judgment, and the `video-editing` (higgsedit) workflow tool for the actual cut/compose — real per-frame control, native text/graphics compositing, and far more reliable than hand-rolled ffmpeg drawtext. No synthetic B-roll, no AI voiceover standing in for a real one. If cutting from one long source is slow (HDR footage can make Chrome-engine seeking crawl), pre-trim each beat into its own short file with ffmpeg first, then compose those — much faster. **Use `p.frame()` to render and look at proof stills for each beat (open, entrance, signature moment) before the final render** — that's the workflow's own built-in check, not something to skip because a post-render pixel check (step 3e) also exists; the two catch different mistakes (composition/framing vs. wrong-cut-landed). Render the final pass with `higgsedit render --engine node` (roughly 4x faster than the default Chrome engine for footage) once graphics are proofed.
3b. **Sound effects:** there is no standalone SFX/music generation tool available here — `generate_audio` is speech-only (text-to-speech) and explicitly must not be used for SFX. A tasteful synthesized cue (e.g. a short tone/noise burst shaped with ffmpeg, paired with a quick on-screen flash) is a legitimate stand-in for a hit moment, but say plainly in the digest/Slack post that it's synthesized, not a real or licensed sound effect — never imply otherwise.
3c. **Burn captions when the clip has spoken dialogue worth reading** (added 2026-08-31, per Ash's request to push AI-editing capability further) — use the `subtitles` workflow tool (Whisper timing off the real audio, never guessed) with `bold --font-key tiktok` as the default look. This is a real, high-value capability that earlier runs skipped entirely; it's not optional-nice-to-have when a line is doing comedic work (e.g. "the public loves you right now") — burned captions are standard for retention on this format and cost nothing extra to add. Skip only when the beat has no legible spoken line (pure crowd noise/music). Keep the clean unsubbed render too — captions layer on top, they don't replace the master.
3d. **Before staging, run `virality_predictor`** on the finished cut (upload + confirm first; the tool caps input at 16s, so predict against a trimmed copy if the final cut runs longer, but stage the full-length edit to Ash). Report the scores (overall/hook/sustain) honestly in the Slack post — they're predictive proxies, not guarantees, but a low hook score with strong sustain is a real signal the opening 2 seconds needs another pass before spending Ash's review time on it.
3e. **Verify the edit actually has the cuts you think it does before staging — don't trust ffmpeg's scene-cut filter for this.** It gives false negatives on same-location footage (same alley/lighting across beats reads as "no cut" to it even when the source genuinely changed). Instead, for each cut boundary, extract a downscaled frame from the render and find its nearest match (lowest pixel MAD) among frames sampled from every candidate source beat — a match to the wrong beat, or no clear low-MAD match, means the cut didn't land where intended. This caught a real false alarm once (agent wrongly told Ash a correct edit was broken based on the scene-cut filter alone) — don't repeat that mistake in either direction: verify with real pixel comparison before asserting the edit is right OR wrong.
3f. **When asking Ash for creative direction (hook wording, pacing, style), use `AskUserQuestion` with concrete options, not open-ended text.** He asked for this explicitly (2026-08-31) — give him things to pick from (e.g. 3-4 hook-line variants matching the four patterns in step 2, or named pacing options) rather than an open "what do you want" question.
4. **Stage, do not publish.** Post the draft(s) to `#agent-pub-crawl` for Ash's 👍, and also make the actual video file available directly (not just a description) since that's what's needed for real review. **Delivery link, status as of 2026-08-31 — unresolved, don't assume either way:** Ash hit "Access denied" once on a Higgsfield CDN link (`d2ol7oe51mr4n9.cloudfront.net/...`), but a later same-domain link (from the standard `media_upload`+PUT+`media_confirm` flow) was fetchable with no auth from inside the sandbox — so it's unclear whether the CDN is actually blocked for Ash's browser or that first failure had a different cause. Until Ash confirms one way or the other, use tmpfiles.org as the primary link (that specific action has his one-time nod, given 2026-08-31, since it publishes to a third-party host) **and also include the CDN link from `media_confirm` as a second option**, asking him to say which one actually opened — that answer resolves this for every future run instead of guessing per-post. Say plainly that the tmpfiles.org link is temporary/unlisted and may expire (roughly an hour) — post it close to when Ash will actually check, not hours ahead. **Do not attempt to relay the raw video file through this session's own chat/tool output as a substitute for a link — verified 2026-08-31 that large binary transfers this way are unreliable (a checksum-verified corruption on a file well under any obvious size limit), so it's not a fallback worth retrying.** Nothing goes live without an explicit approval reaction/reply — this is the "Ash approval required: publishing social content" rule from `CLAUDE.md`, not optional even for on-brand content. Also be upfront that frame-by-frame visual review by the agent itself is still not possible (network policy blocks pulling image/video bytes back into this session) — the scene analysis in step 3 is real visual understanding, but it isn't the same as watching the final render; always ask Ash to eyeball it before approving.
5. Once (and only once) Ash approves a specific piece in that thread, publish it and log it to "Incidenti e interventi" (`455a9b8c-37db-4b92-96bf-2f0dd0aee514`) as a Deploy entry, Sito = Tour.
6. If a week produces nothing (no usable real footage, no clear hook, no approval yet on last week's batch), log that too — an empty week is still a logged outcome, not silence.
